Exercício e Avaliação Prática de SQL — Politec

Esta atividade acadêmica representa uma prática avaliativa na disciplina de Banco de Dados realizada no curso Técnico em Informática na Politec (arquivo prova_jair.sql).

O exercício abrange os conceitos centrais de DDL (Data Definition Language) em sistemas gerenciadores de banco de dados relacionais (SGBD MySQL / MariaDB), com foco na estruturação correta de tabelas, escolha de tipos de dados, restrições de integridade e integridade transacional (engine InnoDB).

Atividade Escolar da Politec:

Este exercício integra as atividades curriculares e avaliações práticas de banco de dados desenvolvidas em sala de aula na Politec. Não representa um sistema completo com funcionalidades inventadas, mas sim a criação rigorosa da estrutura relacional.

Script SQL Real Desenvolvido (prova_jair.sql)

prova_jair.sql — Criação das Tabelas tb_projetos e tb_skill 
-- Tabela para armazenamento de projetos
CREATE TABLE tb_projetos (
    pro_codigo int(11) NOT NULL AUTO_INCREMENT,
    pro_descricao varchar(200) DEFAULT NULL,
    pro_foto varchar(250) DEFAULT NULL,
    pro_status char(1) DEFAULT NULL,
    pro_data_cadastro timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (pro_codigo)
) ENGINE=InnoDB AUTO_INCREMENT=0 DEFAULT CHARSET=latin1;


-- Tabela para armazenamento de habilidades (skills)
CREATE TABLE `tb_skill` (
    `ski_codigo` int(11) NOT NULL AUTO_INCREMENT,
    `ski_descricao` varchar(150) DEFAULT NULL,
    `ski_porcentagem` int(11) DEFAULT NULL,
    `ski_data_cadastro` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`ski_codigo`)
) ENGINE=InnoDB AUTO_INCREMENT=0 DEFAULT CHARSET=latin1;
Conceitos Técnicos Aplicados no Script:
  • Chave Primária (PRIMARY KEY): Definição dos campos pro_codigo e ski_codigo como identificadores únicos e não nulos.
  • Auto Incremento (AUTO_INCREMENT): Geração sequencial e automática de identificadores para novos registros.
  • Carimbo Temporal (TIMESTAMP): Configuração de DEFAULT CURRENT_TIMESTAMP para registrar a data e hora do cadastro de forma automática.
  • Tipagem de Dados: Emprego adequado de INT, VARCHAR para textos descritivos e CHAR(1) para controle de status booleano/flags.
  • Mecanismo de Armazenamento: Utilização da engine InnoDB, que suporta transações seguras (ACID) e integridade referencial.
